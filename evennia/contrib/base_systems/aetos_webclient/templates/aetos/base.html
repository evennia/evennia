{% load static aetos_tags %} {% comment %} Aetos base template. Aetos deliberately does NOT extend Evennia's `webclient/base.html`. That template loads eight third-party resources -- jQuery, Bootstrap, Popper, Favico and GoldenLayout -- for the benefit of the stock GUI. Aetos is vanilla JavaScript and uses none of them, and loading them anyway would mean: * the client breaks on an offline or firewalled network * every player's browser contacts five third parties to play a MUD * one of the URLs is unpinned (`golden-layout.com/files/latest/`), so an upstream change could break every Aetos install without warning * one host (cdn.rawgit.com) is a deprecated service Blueprint section 2.2 sets a core-only dependency target. This page therefore loads nothing but Evennia's own static files and Aetos's own. What this template does replicate is the transport bootstrap: the four template variables `evennia.js` expects, and the script tag that loads it. That file is Evennia's own, served unmodified from Evennia's own static directory -- Aetos neither copies nor patches it, and Evennia's Portal is untouched. The variables come from Evennia's documented webclient view and context processor (`game_name`, `websocket_enabled`, `websocket_port`, `websocket_url`, `browser_sessid`). {% endcomment %} {% comment %} Content-Security-Policy, declared in the document rather than sent as a header, and first in the head because a meta policy governs only what the parser has not yet reached. A contrib cannot set a response header without owning the view or installing middleware, and middleware would apply this to the game's entire website -- front page, admin, wiki -- which is not a decision a webclient makes on a game's behalf. Media a game declares may be hosted anywhere, and the browser fetches it directly -- so a third-party host learns the player's IP address, which is inherent to showing remote media and not something a client should silently prevent. What it need not learn is the URL of the page they were on. A small improvement, stated as one: this matches what modern browsers already default to, and pins it for those that defaulted to sending the full URL. `no-referrer` would be stricter and is not used, because media hosts commonly refuse requests with no referrer and the failure would look to a game like "Aetos does not show my images". {% endcomment %} {% comment %} This page must not be cached. It embeds `browser_sessid` as the websocket's `csessid`, so a cached copy hands the transport a session that no longer exists -- presenting as a client that connects and then does nothing. Caching also pins the asset URLs, so an upgraded Aetos keeps being ignored until the visitor clears their cache, which they have no reason to suspect. The stock webclient view sets no cache headers, and a contrib cannot add response headers without owning the view, so this is declared in the document. {% endcomment %} {% comment %} Inline favicon.
