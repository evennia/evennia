{% extends "aetos/base.html" %} {% load static aetos_tags %} {% comment %} Aetos Web Client page. This template wins over Evennia's own `webclient.html` because a game prepends the Aetos template directory to `TEMPLATES[0]["DIRS"]` (see README.md). It cannot be found by the app-directory loader alone: Django searches every DIRS entry before any installed app, and Evennia always has its own webclient template directory in DIRS. Aetos extends its own base (`aetos/base.html`) rather than Evennia's stock `webclient/base.html`. The stock base loads eight third-party CDN resources for the benefit of the stock GUI; Aetos is vanilla JavaScript and uses none of them. See `aetos/base.html` for the full reasoning. Evennia's transport is still entirely untouched: `evennia.js` is loaded unmodified from Evennia's own static files, and the Portal is not involved. {% endcomment %} {% block styles %} {% comment %} The web app manifest, and the theme colour a browser paints its own chrome with before any CSS runs. Both point at URLs a game only has if it added Aetos's optional urls.py. A missing manifest is a 404 the browser ignores silently and nothing else -- which is the intended behaviour, since the PWA is optional and a game that did not opt in should get no part of it rather than a broken part. The colour is stated literally rather than read from a token: it is consumed before the stylesheet loads, so a variable would be undefined at the one moment it matters. It matches --aetos-bg, and a test asserts they agree. {% endcomment %} {% endblock %} {% block scripts %} {% comment %} The accessibility subsystem loads before everything else. {% comment %} The mode switch. A9, then A10. OUTSIDE THE NAVIGATION LANDMARK, and last, so it sits at the top right on its own. It is not navigation -- it does not take you anywhere, it changes which interface you are in -- and grouping it with Edit Layout and Help made it read as a third button rather than as the control it is. A SWITCH, NOT A BUTTON. `role="switch"` with `aria-checked` announces "on" and "off", which is what this does; `aria-pressed` would announce "pressed", which describes the act rather than the state. The visible track and thumb say the same thing to somebody who can see it, and the thumb's *position* -- not its colour -- is what carries the state. THE ONE CONTROL THAT MUST STAY FINDABLE. Since A10 it is the way back from standard mode, so its size, position and wording are deliberately not governed by the mode: identical whichever one you are in. The floor lives in `accessibility.css`, above the target-size rule it has to beat. It says words rather than showing an icon. An icon here would be a symbol somebody has to recognise before they can ask for help reading symbols. {% endcomment %}
{% comment %} The options are a separate button, and only appear once accessible mode is on. They were behind the switch itself until it was pointed out that flipping the switch presented a panel of options rather than switching a mode -- which is what it looked like, because it was. A control that does two things is read as whichever one you notice first. So the switch switches, and this asks for the settings. Hidden in standard mode because there is nothing there to configure: the accommodations are not applied, and offering to adjust them would be offering to adjust something that is off. {% endcomment %}
{% comment %} Where the accessibility panel renders. Empty and hidden until asked for. Directly after the status bar and before the workspace, so that a keyboard or screen-reader user who has just activated the toggle reaches its contents next rather than after every widget. {% endcomment %}
{% comment %} The two announcement regions. Addendum A.15, A11Y-ANN-001. These are the only live regions in Aetos. Widgets never create their own: a player has one pair of ears and one braille display, so thirty independent live regions do not produce thirty conversations, they produce one conversation with thirty interruptions in render order. The urgent region interrupts and is reserved for connection and session failure. Gameplay never reaches it -- a channel that interrupts constantly stops being an interruption, and then the one message that truly needed to interrupt is the one that gets ignored. {% endcomment %}
{% comment %} The workspace announces staleness for a screen reader. `aria-describedby` rather than a live region: this is a *property* of what is on screen, not an event. The disconnection itself is announced once through the ordinary announcer; this is what somebody hears when they navigate into a panel afterwards and need to know the number they are reading is the last one that arrived. {% endcomment %}
